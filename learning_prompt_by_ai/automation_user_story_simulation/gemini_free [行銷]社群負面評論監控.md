## # 自動化五問

1. 起點: 系統觸發事件 / 使用者行為
   - Facebook 粉絲專頁有使用者新增留言或編輯留言。

2. 終點: 業務完成結果 / 系統狀態
   - 指定的 LINE 群組或相關人員收到包含留言內容、留言者資訊及原始連結的即時通知。

3. 判斷:
   - Trigger condition（觸發條件）：Webhook 接收到 Facebook 留言事件。
   - business rule（關鍵規則 / keyword / threshold）：語意分析或關鍵字比對（如：不滿、憤怒、退款、爛、騙人等）。

4. 失敗處理:
   - API / 系統失敗：若 Facebook Graph API 或 LINE Messaging API 斷線，需紀錄日誌。
   - retry 機制：針對 API 請求失敗進行指數退避（Exponential Backoff）重試。
   - fallback（人工處理）：若自動化服務完全失效超過一定時間，寄送 Email 備援通知。

5. 值得做嗎:
   - ROI summary（時間 / 人力 / 風險）：高。省去行銷人員 24 小時人工監看成本，降低公關危機延遲處理的風險。

---

## # 需求點（Functional Requirements）

- 系統需透過 Webhook 監聽 Facebook 粉絲專頁的留言事件。
- 系統需具備過濾演算法，針對留言內容進行關鍵字過濾或情感分析（Sentiment Analysis）。
- 系統需整合 LINE Messaging API，將篩選後的異常留言推送至指定通訊頻道。
- 系統需提供日誌紀錄，追蹤已通知的留言狀態，避免重複發送。

---

## # 缺少資訊（Missing Requirements）

分類：

1. 業務規則缺失
   - 關鍵字清單：具體需要監控的敏感詞彙清單為何？
   - 負面情緒門檻：若使用 AI 判斷，情緒分數達到多少才觸發通知？

2. 系統整合缺失
   - LINE 通知對象：是發送到特定的 LINE 群組（Notify/Bot）還是個人帳號？
   - Facebook 權限：是否已取得 Page Access Token 及相關 Webhook 訂閱權限？

3. 流程 / 權限缺失
   - 排除清單：是否需要排除特定 VIP 使用者或官方帳號自己的留言？
   - 通知時段：是否為 24 小時不間斷通知，還是特定時段才發送？

4. 資料格式缺失
   - 通知內容模板：LINE 訊息中除了留言文字，是否需要包含留言者大頭照或留言截圖？

---

## # 判斷價值（Business Value）

必須包含：

1. 時間節省：行銷人員無需手動重新整理網頁監看留言，每日節省約 2-4 小時無效工時。
2. 風險降低：將公關危機反應時間從「小時級」縮短至「分鐘級」，有效防止負面評論發酵。
3. 自動化程度提升：實現從社群監測到內部告警的完全自動化閉環流程。
4. 可追蹤性：所有被標記為負面的留言皆有紀錄可查，方便後續彙整公關處理績效。
