## # 自動化五問

1. 起點: 倉庫管理員更新庫存表（每日庫存數據更新）

2. 終點: 系統自動觸發採購預警，通知採購人員並完成供應商下單流程（或進入待處理狀態）

3. 判斷:
   - Trigger condition（觸發條件）:
     - 庫存表更新事件（手動更新 / 系統同步）
   - business rule（關鍵規則 / keyword / threshold）:
     - A4紙庫存 < 5箱 → 觸發警報
     - 墨水庫存 < 5箱 → 觸發警報
     - 任一品項低於閾值即觸發
     - 庫存數據需為最新一次更新結果

4. 失敗處理:
   - API / 系統失敗:
     - 庫存表讀取/同步失敗需 log 與告警
   - retry 機制:
     - 定時重新讀取庫存表（例如每小時 retry sync）
     - 通知失敗（email/IM）retry 3 次
   - fallback（人工處理）:
     - 進入採購待處理清單（manual queue）
     - 倉庫與採購人員手動確認庫存狀態並補單

5. 值得做嗎:
   - ROI summary（時間 / 人力 / 風險）:
     - 時間：減少人工每日檢查庫存與提醒成本
     - 人力：降低倉儲與採購間溝通成本
     - 風險：避免耗材斷料導致作業中斷（高營運風險）
     - 自動化：中高（可由人工表格升級為自動監控系統）
     - 可追蹤性：庫存變化與採購決策可完整記錄

---

## # 需求點（Functional Requirements）

- 系統需接收或同步倉庫庫存表資料（Excel / Google Sheets / ERP）
- 系統需定期或事件式更新庫存數據
- 系統需監控 A4 紙與墨水庫存低水位（<5箱）
- 系統需自動觸發採購預警通知（email / IM / dashboard）
- 系統需建立採購待辦清單（purchase queue）
- 系統需記錄所有庫存變化與警報歷史（audit log）
- 系統需支援人工覆核與補單流程

---

## # 缺少資訊（Missing Requirements）

### 1. 業務規則缺失
- 5箱是否固定閾值或可動態調整
- 是否有安全庫存（buffer stock）概念
- 是否分不同倉庫或單一庫存總量

### 2. 系統整合缺失
- 庫存表來源（Excel / Google Sheets / ERP / WMS）
- 是否已有採購系統（ERP / SAP / 手動流程）

### 3. 流程 / 權限缺失
- 誰負責最終下單（採購 vs 倉管）
- 是否需要主管審批採購單
- 緊急採購是否有 bypass 流程

### 4. 資料格式缺失
- 庫存表 schema（品項 / 數量 / 單位 / 更新時間）
- 採購單格式與供應商資料結構
- 供應商聯絡與下單方式（API / email / phone）

---

## # 判斷價值（Business Value）

1. 時間節省
- 減少人工每日盤點與通知採購時間

2. 風險降低
- 避免耗材斷料導致營運中斷風險

3. 自動化程度提升
- 從人工監控庫存轉為系統化預警

4. 可追蹤性
- 庫存變化、警報與採購行為可完整追蹤
