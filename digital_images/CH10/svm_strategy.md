# 支持向量機 (SVM) 多分類策略：OVO 與 OVA 優缺點對比

支持向量機（SVM）本質上是一個**二分類器**（只能區分 A 或 B）。當面對多分類任務（例如手寫數字 0~9 分類，共 10 個類別）時，主要有兩種經典的延伸策略：**OVO (One-vs-One)** 與 **OVA / OVR (One-vs-Rest)**。

> 💡 **註：** OpenCV 的 `cv2.ml.SVM_C_SVC` 底層預設採用的是 **OVO 策略**。

---

## 1. OVO (One-vs-One) 一對一策略

### 📌 核心概念
將 $N$ 個類別**兩兩配對**，為每兩個類別各自訓練一個獨立的二分類器。
* **舉例說明**：若有 `0`, `1`, `2` 三個數字，會訓練 3 個分類器：(0對1)、(1對2)、(0對2)。
* **預測方式**：讓所有分類器進行投票，最高票的類別勝出。
* **分類器總數**：$\frac{N(N-1)}{2}$ 個。

### 📊 優缺點分析
* **優點 👍：**
  * **抗資料不平衡能力強**：每次訓練只拿兩個類別的資料，數量比較均勻。
  * **單個分類器訓練速度快**：因為每次訓練只用到一小部分資料（少部分樣本），當總資料量極大時，拆開訓練反而比一次練全部還快。
  * **分類邊界較精準**：在處理複雜、重疊的局部邊界時表現優異。
* **缺點 👎：**
  * **分類器數量爆炸**：如果類別很多（例如 100 類），分類器數量會飆升到 4,950 個，**預測（Predict）時需要消耗較多時間與記憶體**。

---

## 2. OVA / OVR (One-vs-Rest / One-vs-All) 一對多策略

### 📌 核心概念
針對每一個類別，都訓練一個「該類別 vs 其他所有類別總和」的分類器。
* **舉例說明**：若有 `0`, `1`, `2` 三個數字，會訓練 3 個分類器：(0對非0)、(1對非1)、(2對非2)。
* **預測方式**：看哪一個分類器輸出的信心分數（機率/距離）最高，就屬於哪一類。
* **分類器總數**： $N$ 個。

### 📊 優缺點分析
* **優點 👍：**
  * **分類器數量極少**：有幾個類別就只要練幾個分類器（100 類就只要 100 個）。
  * **預測速度非常快**：因為需要評估的模型數量少，預測效率極高。
  * **模型體積小**：儲存下來的 XML 或模型檔案通常比較輕量。
* **缺點 👎：**
  * **嚴重的資料不平衡問題**：訓練 (0對非0) 時，「非0」的資料量（包含1~9）會遠遠大於「0」的資料量，導致 SVM 容易偏心，影響準確度。
  * **單個分類器訓練很慢**：每次訓練都必須吃進「全體」的訓練資料，計算壓力大。

---

## 🏎️ 快速對比總結表

假設你有 $N$ 個類別，總資料量為 $M$：

| 特性 / 比較項目 | OVO (一對一) <br>`(OpenCV 預設)` | OVA / OVR (一對多) |
| :--- | :--- | :--- |
| **分類器總數量** | 多 $\left(\frac{N(N-1)}{2} \text{ 個}\right)$ | 少 ($N$ 個) |
| **單個分類器資料量**| 少（僅包含該兩類的樣本） | 多（每次都必須載入全體樣本） |
| **抗資料不平衡** | **極強** 🌟 | 較弱（少數類容易被多數類淹沒） |
| **訓練速度 (Train)**| 類別少、資料量大時**較快** | 類別極多時較快，但記憶體消耗大 |
| **預測速度 (Predict)**| 較慢（需要跑完所有模型的投票） | **極快** 🚀（只需跑 $N$ 次模型） |

### 🧠 為什麼 OpenCV 預設選擇 OVO？
在經典的影像特徵分類中（如你目前做的 HOG + MNIST 數字分類），**資料不平衡**對於 SVM 劃分幾何邊界（Hyperplane）的殺傷力非常大。OVO 雖然在預測時要跑比較多分類器，但它能確保模型在**準確度 (Accuracy)** 和**邊界穩定度**上取得最頂尖的表現！
