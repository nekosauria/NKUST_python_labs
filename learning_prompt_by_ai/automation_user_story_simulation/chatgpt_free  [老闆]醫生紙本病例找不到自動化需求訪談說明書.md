## # 自動化五問

1. 起點: 醫療場域中醫師需要調閱病歷，但紙本病歷未能即時定位或遺失

2. 終點: 病歷能被可靠定位、補齊或數位化存取，確保醫療作業不中斷

3. 判斷:
   - Trigger condition（觸發條件）:
     - 病歷查找請求發生但紙本檔案未找到 / 延遲超過可接受時間
   - business rule（關鍵規則 / keyword / threshold）:
     - 病歷唯一識別：病歷號 / 身分證 / 就診時間
     - 查找超時（例如 > 5 分鐘未定位）觸發異常流程
     - 病歷狀態：已歸檔 / 借出 / 遺失 / 待數位化

4. 失敗處理:
   - API / 系統失敗:
     - 若導入電子系統：檔案系統 / DB / 掃描系統失敗需記錄 log
   - retry 機制:
     - 查詢系統重新索引（re-index）
     - 多條件重試查找（模糊搜尋 → 關鍵字 → 手動清單）
   - fallback（人工處理）:
     - 紙本調閱流程升級（行政/護理站人工追查）
     - 啟動補登記流程（病歷補建 / 補掃描）

5. 值得做嗎:
   - ROI summary（時間 / 人力 / 風險）:
     - 時間：減少醫師等待病歷時間，提高看診效率
     - 人力：降低護理/行政人員人工找檔負擔
     - 風險：降低病歷遺失導致醫療判斷資訊不足風險
     - 自動化：若導入電子病歷可大幅提升檢索效率
     - 可追蹤性：病歷存取紀錄可完整追蹤責任鏈

---

## # 需求點（Functional Requirements）

- 建立病歷唯一識別系統（病歷號 / 身分證 / 就診ID）
- 建立病歷索引與查詢系統（支援快速檢索）
- 建立病歷狀態管理（在庫 / 借出 / 遺失 / 數位化）
- 建立病歷查找失敗通知機制
- 建立病歷掃描與數位化流程（紙本轉電子）
- 建立病歷存取 log 記錄系統（audit trail）
- 建立異常查找與人工補登流程

---

## # 缺少資訊（Missing Requirements）

### 1. 業務規則缺失
- 病歷保存年限與法規要求
- 遺失病歷是否允許補建或需法律流程
- 查找失敗的定義（時間 / 次數）

### 2. 系統整合缺失
- 是否已有 HIS（Hospital Information System）
- 是否已有電子病歷系統（EMR/EHR）
- 是否需要 OCR / 掃描整合系統

### 3. 流程 / 權限缺失
- 誰有權限借閱/修改病歷
- 病歷遺失時責任歸屬與處理流程
- 是否需要跨科室協作流程

### 4. 資料格式缺失
- 病歷資料結構（紙本索引 vs 電子欄位）
- 病歷掃描檔格式（PDF / image / DICOM）
- 查詢索引資料結構設計

---

## # 判斷價值（Business Value）

1. 時間節省
- 減少醫師與行政人員查找病歷時間

2. 風險降低
- 降低病歷遺失造成醫療誤判風險

3. 自動化程度提升
- 從紙本人工查找轉為系統化索引與檢索

4. 可追蹤性
- 病歷存取與異動全流程可追蹤與稽核
